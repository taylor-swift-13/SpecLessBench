# SpecLessBench 第一版设计

## 目标

给定两个固定且结构不同的实现，评测模型能否发现并证明它们之间的行为对应。原生 Rocq 赛道着重算法与表示之间的关系推理；C／Clight 赛道着重将这种推理延伸到控制流、状态和内存操作。

核心创新点是**不提供独立的声明式功能规约，直接在两个实现之间证明等价**。每题只需固定比较范围：输入域、前置条件和可观察接口。它们不是第三份“正确行为”规约；参考实现提供行为基准，待验证实现必须与之对应。

## 动机：把实现替换转化为行为保持证明

精确表达程序行为的声明式规约可能很难生成、审查或评估，而简单、可信、易审查的参考实现可以直接充当**可执行行为基准**。例如，二进制解析器需要处理长度字段、字节序、错误输入和错误返回；完整规约可能接近重新写一次解析器。SpecLessBench 不要求先手工写出这样的独立规约，再证明两个实现各自满足它，而是直接比较参考解析器和优化／迁移版本的形式化行为。

这不是唯一的动机。即使声明式规约容易写，行为保持本身仍有价值：排序可以用“结果有序且是输入的排列”来描述，但仍需要证明一次优化或替换没有改变行为。阶乘、矩阵乘法等程序常以可执行算法自然表达；在受限验证语言中，性质也可能更容易编码成可执行形式，而不是富含量词的声明式逻辑。SpecLessBench 考察模型如何解释不同计算过程为何产生相同观察。比如插入排序和选择排序的中间数组、循环次数和状态推进方式可能都不同，证明通常需要适当的抽象、关系不变式或共同中间模型。

这一目标支持多种实现替换场景：

| 场景 | 参考实现 | 待验证实现 |
|---|---|---|
| 性能优化 | 简单、直接的算法 | 分块、向量化或缓存优化的版本 |
| 数据结构替换 | 列表或数学映射 | 哈希表、平衡树或压缩表示 |
| 浮点计算优化 | 运算顺序明确的标量版本 | SIMD、GPU 或融合运算版本 |
| 重构与迁移 | 原有程序 | 重构后或另一语言的实现 |

等价证明只保证新版本与参考版本的行为一致，不证明参考版本符合用户意图。若参考版本有错误，等价实现也可能保留该错误；因此，信任重点集中在易于审查的参考实现上。benchmark 应把这一点作为范围边界，而不是把实现等价宣称为意图正确性。

“不提供规约”在这里指没有独立的函数级后置条件或数学结果函数。任务仍需给出最小的输入和观察边界，否则等价关系本身无法判断。任务目标允许两种机器可检查的证书：全域等价证明，或一个满足前提且两边观察不同的具体反例及证明。证明失败或超时不能推导出不等价；没有有效反例证书的任务尝试计为失败。

## 范围

第一版要求同一任务有三个平台版本：

1. **原生 Rocq**：目标是固定输入域上的外延相等。题目给出两个 Rocq 实现和固定目标定理。
2. **C／Clight**：题目给出两个 C 实现，使用 `clightgen` 导出 Clight AST，并基于 CompCert 提供的 Clight 语义证明行为等价。Clight AST 是证明对象；不会假设 C 被自动翻译成普通 Rocq 函数。
3. **原生Lean**：具体可执行实现与对应输入域/观察，提供未证明的等价／反例目标；与原生Rocq版、CompCert版通过共同输入做差分检查。

第一版优先选择确定、终止、无外部 I/O 的程序。C 题优先使用固定数组和结构体。浮点、动态内存和复杂外部调用暂缓，因为它们需要额外定义观察等价。

复杂数据结构使用预分配节点、有限 arena 和显式工作栈，以覆盖真实指针结构与函数调用。若将来源的动态分配器改为 arena，这就是派生程序，须记录修改；原版动态分配语义留作扩展。每道题的入口及所有可达辅助函数体共同构成固定实现，只有函数声明和既有功能契约不足以构成一个完整任务。

Lean已按新要求纳入。每个实现组为划分、版本和成本单元，派生平台实例不重复计算组成本。构造中可根据差分反例修订实现和题目，冻结后求解者不能修改；所有发现与修订须入追加日志。最终目标在构造阶段暂不要求证明。

## 固定任务要素

每题固定并保护：

- 两个待比较的实现；
- 输入类型、输入域和前置条件；
- 对外可观察的结果范围；
- 等价证明／反例证明的固定证书目标；
- 证明所需的语义接口和基础环境。

模型只能在指定的证明区域增加辅助定义、引理和证明，不得修改实现或目标定理。证明方法不设限：允许通过共同抽象模型、关系推理或分离逻辑完成证明。

### 原生 Rocq 的目标

等价实例的目标形态为：

```coq
forall input, impl_A input = impl_B input.
```

对每个固定程序对，agent 需要构造以下二选一的可检查证书：

```coq
(forall input, valid_input input -> impl_A input = impl_B input) \/
(exists input, valid_input input /\ impl_A input <> impl_B input).
```

正例提供等价证明；负例提供反例证明。不能仅把超时、失败或模型自报的“不等价”计为反例。

上述析取只表示两种合法结果的概念分类，**不能单独作为可计分的Prop证明**。当前接受接口要求显式JSON分支；反例还须提交具体输入和观察，并证明专门化目标。否则经典逻辑可非构造性地证明某些总函数的裸析取，绕过行为判断。见[证明接口v1](../benchmarks/proof-interface/README.md)。旧析取模板仅作为历史设计保留。

### C／Clight 的目标

每题定义允许的初始状态关系和输入前置条件。正例证明两边都从相关初始状态安全执行并终止，且返回值及题目指定的输出内存区域满足观察关系。负例提供一个满足前提的相关初始状态及两边的安全有限执行证书，证明返回值或指定输出内存观察不同。第一版负例优先采用这种可给出有限见证的情况，不把“无法证明终止”当作反例。最终整块内存不要求相等；栈布局、临时存储和其他未观察状态可以不同。

每题必须明确可观察行为的边界，包括返回值、哪些内存修改、I/O 和终止性。第一版不包含外部 I/O；C 题的返回值、指定输出内存和安全终止要求构成其任务级观察。将来若加入浮点程序，必须区分逐位相等、数学值相等和误差界内接近等不同目标，不能只用未定义的“等价”概括。

## 按实现差异选题

题目按证明挑战和实现差异选择，不按算法名称堆数量。优先覆盖：

- 递归结构差异：普通递归与累加器尾递归；
- 算法差异：插入排序与选择排序等；
- 计算策略差异：朴素字符串匹配与 KMP，递归计算与动态规划；
- 数据表示差异：列表集合与搜索树集合，单列表队列与双列表队列；
- 控制流差异：双循环与融合循环，递归遍历与显式栈遍历；
- 内存操作差异：临时缓冲区与原地反转，不同数组旋转算法。

排序作为基础题型保留，但不作为试验集主体。数据结构任务应比较合法操作序列产生的可观察结果，而不是内部状态。

复杂组新增侵入式双链表、环形缓冲区、树镜像、BST 删除、AVL 插入、并查集、优先队列、跨文件 Dijkstra、带 union 的 AST 解释器和 VST pile 模块替换。L4 暂用于需要跨递归调用或模块组合多个关系与堆不变式的任务，函数数目本身不决定难度。尤其注意：并查集比较连通性而非根编号，BST 比较键值查询而非树形，双链表需要观察反向遍历，AVL 少一次旋转不自动构成可观察反例。

## 家族、划分和报告

多个实现归入同一程序家族。实现组合无需全部两两枚举为独立样本。数据集按家族划分，确保同一家族的所有任务只进入 train、dev、test 中的一个集合。

报告至少包含：

- **按题证书成功率**：提交且通过内核检查的等价证明或反例证明数除以任务数；
- **正例等价证明率**和**负例反例证明率**，分开报告；
- **按家族成功率**：先计算每个家族内部的平均成功率，再对家族等权平均。

同时报告两种指标，避免实现组合较多的家族在汇总分数中占据过大权重。
